Nebo REV218: bounded GitHub Actions recovery infrastructure

This isolated CI branch preserves REV217 identity by reference. It has no local
recovery ancestry and contains no original compiler, runtime, frozen recovery
metadata, private host identifier, private logs, third-party binary or credential.
The existing owner authorization permits publication of these newly authored CI
files. The project license is preserved; this is not a new public API/license
decision and does not resolve any pending normative or third-party provenance gate.

One push on ci/nebo-recovery-rev218 runs a maximum 20-minute infrastructure job
on ubuntu-24.04, with contents:read and actions pinned to reviewed official SHAs.
No merge, tag, release, unbounded rerun or next-revision execution is performed.
The absolute authorized session deadline is in ci/session.json. Expired sessions
cannot admit the smoke. No native campaign is admitted by this snapshot.

The smoke records the real runner identity and resource/capability observations,
then tests normal completion, timeout, cancellation, descendant cleanup across
new sessions, monitor exit, log/partial-evidence preservation, deadline rejection
and input tampering detection. The systemd adapter uses the same cgroup-wide
kill principle as the previously prepared private guard. It is not a claim that
the original physical-machine guard works unchanged on a hosted virtual machine.

All uploaded files are generated by these reviewed synthetic smoke cases. They
contain no original packet or environment dump. Artifacts in a public repository
are not private; authenticating their hashes does not make private data publishable.

The original packet is withheld because publication review found private host
metadata and unresolved binary/dependency redistribution provenance. The existing
frozen hashes are not changed to redact those files. A separately authorized
private execution destination with the unmodified payload is required unless
those publication blockers can be legitimately resolved.

Infrastructure PASS is never POS/NEG/META/COMP/REG/R006 acceptance. Native counts
remain zero until the real frozen admission executes and its own receipts and
tool provenance validate. R006 and checkpoint/seal require a full authenticated
checkout; this deliberately minimal branch does not supply one.
