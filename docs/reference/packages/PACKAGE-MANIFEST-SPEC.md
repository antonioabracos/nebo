# Native offline package manifest

Public owner: `neboc package freeze|verify|restore|build`, implemented by
`compiler/sdk/package_manager.py` through the existing package command host.

`nebo.package.json` has exactly these fields. Unknown fields, duplicate JSON
keys, nonfinite numbers and build hooks are rejected. Canonical encoding is
UTF-8, sorted keys, compact separators and one trailing newline. Source bytes
are preserved. Formatting and member argument order do not affect a lock.

```json
{"schema":"NEBO-PACKAGE-MANIFEST-v2","package":"example.app","version":"1.1.0","edition":"1","targets":["x86_64-systemv-elf-linux"],"source_roots":["src"],"modules":[{"logical":"g180_app","source":"src/main.no"}],"dependencies":{"example.left":{"requirement":"^1.0.0","pin":"1.1.0"},"example.right":{"requirement":"^1.0.0","pin":"1.1.0"}},"capabilities":[],"features":["interface-units"],"build_profiles":{"default":{"optimization":"none"}},"target_packs":["x86_64-systemv-elf-linux"],"metadata":{"description":"Local application"}}
```

PackageId is a lowercase dotted identity with 2–8 alphanumeric components,
each beginning with a letter, at most 100 bytes. It is independent of a native
logical module identifier. One version per PackageId is permitted in a graph.
Versions are canonical `major.minor.patch`, each component 0–65535; prerelease
and build suffixes are outside this bounded profile. Edition is `1`.

Source roots are distinct relative paths. Each module has a unique logical
name and a `.no` source contained in exactly one declared root. Every root
must be used. The reserved `interfaces` root is generated by the native writer.
Only declared sources and the canonical manifest enter a package; surrounding
files are not traversed. Each source is at most 4096 bytes, matching the native
interface owner. JSON inputs are at most 64 KiB. Each package has 1–3 modules;
the complete native graph currently requires exactly three modules across
1–3 packages. Larger graphs are rejected before compilation. This is a
material public bounded profile, not a claim of arbitrary package scale.

Dependencies map PackageId to an exact `pin` and a declared `requirement`.
Requirements support exact triples, caret and tilde; there is no version
search or network fallback. The chosen pin must match a workspace member.
Capabilities are empty: import grants no authority. Build profiles currently
admit only the default unoptimized native profile. `target_packs` must select
the same supported Linux x86-64 System V ELF target as `targets`. Metadata
contains at most 16 inert string pairs, with key/value bounds 64/256 characters.

Exactly one feature selects native linking: `interface-units` consumes the
native `.ni` material exports; `source-units` consumes sources. All packages
must agree. Requesting both modes, unsupported features, targets, editions or
profiles fails. Neither mode provides lifecycle hooks or dynamic imports.

The workspace file has exactly `schema`, `root`, `entry`, `members`:

```json
{"schema":"NEBO-PACKAGE-WORKSPACE-v1","root":"example.app","entry":{"package":"example.app","module":"g180_app"},"members":["app","left","right"]}
```

Members are distinct non-overlapping paths under the workspace file's directory.
Package cycles, unreachable members and logical name collisions fail. Native
ModuleId and module edges come from `module-info`/`module-graph`; cross-package
edges must equal declared dependencies. Native visibility is enforced. Native
dependency-first order is recorded; non-entry implicit initialization is rejected.

The RF27 schema-1 path commands remain compatible. This versioned manifest
schema adds a material exact-pin profile; it does not change the product release
version. The old symbolic `NEBO-PACKAGE-MANIFEST-v1` `.pkg` verifier is rejected
as insufficient source/interface/build evidence. Legacy numeric Assembly package
records remain internal bounded records, not JSON manifest parsers.
